# Automatic Codex guard

This mode adds automatic checks to the existing workflow. It does not replace research or independent review. Hooks must be loaded, enabled and trusted in the executing Codex session. Installing a skill or copying these files does not establish activation.

## Activation and scope

Start the human prompt with `$deep-research-circuit`, `Use Deep Research Circuit`, or `Run Deep Research Circuit`. An optional first-line `[calls=12]` sets the initial stage from 0 to 100; the default is 12. Optional `[ceiling=30]` sets a hard cumulative covered-call ceiling, at least the initial allowance and at most 10000. Without it, the coordinator may approve justified extensions. Natural-language time and spending limits still bind the workflow; the hook does not convert them to dollars or minutes. Quoted mentions and generic research requests do not activate it. The hook supplies a unique evidence directory inside the current study's `research-workspaces/`, remaining units and limits. The package directory and its descendants, and a root containing `.hyperresearch-plugin-development`, are rejected. Continue using the original absolute study root for upstream commands and subagents; the guard directory holds only this draft's evidence/manifest/review.

The allowance is deliberately conservative: it counts intercepted local tool calls, including arbitrary shell/browser calls, not just tools named search. Recognised top-level query/URL batches are charged per listed entry. Opaque programs or browser scripts count as calls, not their hidden internal requests; there is no universal query, token or dollar cap. An initial reserve of 12 completion units permits edits and reviewer dispatch; each approved extension adds 4 completion units. Strict local evidence/plugin reads, messages to existing agents, waits, listing and interruption cost zero, so control and assessment remain possible at exhaustion. Direct local validator/clock commands cost zero units so exhaustion cannot prevent checking clearance. The networkless code-mode wrapper also costs zero units; its nested tool calls are separately charged where Codex intercepts them. The ledger retains call IDs for replay protection without a separate hidden call-count ceiling.

The same active run is reused across follow-ups and compaction. Repeating the invocation or changing `[calls=...]` in a follow-up does not replenish it. A human `/drc end` prompt ends the guard without declaring success; a later explicit invocation creates a new run. Do not send, manufacture or simulate that user control yourself.

The final quarter of each approved stage is reserved for the strongest unresolved leads, starting within the original allowance. The hook signals that transition; it does not judge source value. Read [search-extensions.md](search-extensions.md): workers request bounded further work, the host-identified coordinator decides, and registered leads retain their original details and action history. Initial allowance exhaustion alone cannot justify closure or discarding a lead. Independent review challenges both premature stopping and unnecessary searching.

Codex documents parent session identity on child hooks. The guard also associates host-provided `SubagentStart.agent_id` with the parent for hosts delivering that child identity. Parent and children then use one atomic ledger. Coordinator decisions additionally require the original host session and transcript path, no non-null child identity fields, and no observed ambiguity. Missing provenance or a known child transcript cannot approve. This distinction was observed on the tested Codex host; it is not proved for hosts with indistinguishable parent/child callbacks. Neither model-supplied role/run labels nor inherited environment variables establish authority. Start a fresh human-invoked run when upgrading from a pre-extension guard, whose active runs lack coordinator provenance. Unrecognised or non-hooked child paths remain a limitation; do not claim their coverage without a runtime observation.

## Finish without a loop

Save `claims.json` and the actual independent review as `review.json` inside the supplied evidence directory. Artifact/report paths stay relative to it, as required by the existing validator. The independent reviewer must personally assess the final draft and supporting sources. Never manufacture an attestation to silence a hook.

Before final review, the coordinator records lead dispositions and closure. Include the automatic `research-scope.json` source and a visible coverage/uncertainty claim in the existing manifest and genuine independent review. New research calls or control changes invalidate closure. Complete research/calculations first; use literal local reads, direct validator commands and completion tools during review. At Stop, the guard freezes the manifest, report, review and source files in a disposable snapshot, runs the actual validator and scope checks against those same bytes, and rejects changed live inputs or ledger revision. It compares generated final text with successful `render` output, ignoring only surrounding whitespace. It writes `guard-check.json`. If this fails, it requests at most one correction for the run. A second failure stops automatic continuation and displays **NOT CLEARED**. It does not silently restart research or increase the allowance.

After exhaustion, use a direct `python3 /absolute/path/to/validate_claims.py check /absolute/evidence/claims.json --review /absolute/evidence/review.json` to inspect failures. Use `python3 /absolute/plugin/path/hooks/guard.py clock` to obtain an actual timezone-aware timestamp for a newly created local calculation record; do not guess it. Literal `cat` reads of files inside the evidence or plugin directories are allowed without charge, including relative paths resolved against the tool's workdir and simple `;`/`&&` cat chains. Arbitrary programs, substitutions, pipelines and multi-line commands are not exempt. Use `apply_patch` for record/draft edits, rather than an arbitrary shell script after exhaustion. Actual Codex collaboration-name variants are recognised; dispatch uses completion units, while existing-agent communication remains available at exhaustion. Useful unresolved findings may be qualified and independently reviewed; an explanatory failure message can be delivered, but remains uncleared rather than being disguised as a passed report.

## Exact protection boundary

- A supported `PreToolUse` denial prevents that covered call from running. Reservations are atomic and repeated delivery of the same call ID does not double-charge it.
- Registered leads must be dispositioned and deferred material uncertainty must remain in the report. The guard cannot identify every valuable source or determine whether an explanation is true; independent assessment remains necessary.
- Stop is an audit/continuation hook. It cannot withhold, replace or retract text already generated. The script does not call it a pre-publication filter.
- Hosted web search, specialised paths outside local hooks, existing long-lived processes, hook loading/trust failures and hook process timeouts can bypass these checks. Hook code catches its own errors and returns explicit decisions, but cannot catch a failure that prevents it running.
- The model and hooks run as the same local user. Their files, ledger and evidence are not protected from deliberate modification. The validator also does not authenticate source or reviewer identity.
- A fully non-bypassable system would require a separate controller owning protected state, exposing only metered tools and releasing only cleared output. This plugin does not provide that controller or silently change global permissions to approximate it.

Hook state is local SQLite under `PLUGIN_DATA`; it records counters, request hashes, paths and compact event outcomes, not raw conversation transcripts. No network/model call is made by the guard itself. Ending a run preserves the audit record. Other chats remain inactive unless explicitly invoked.

Source contract checked on 2026-10-23: [Codex hooks](https://learn.chatgpt.com/docs/hooks) and [plugin packaging](https://developers.openai.com/plugins/build/plugins). These describe capability; an actual callback receipt is needed to establish local activation.
