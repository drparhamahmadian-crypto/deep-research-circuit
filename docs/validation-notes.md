# Validation notes

Deep Research Circuit gives the research procedure, semantic reviewer and record checker different jobs. The reviewer examines meaning, source identity, competing evidence and omissions. The checker verifies the supplied records and the version bindings recorded in that review.

## What a successful check establishes

The marked claim text agrees with the manifest. Cited artifacts have the recorded bytes, source identifiers, locators and quoted text. The review binds to the same report and manifest and contains the required coverage and verdicts. Rendering succeeds after these checks pass.

The checker records reviewer IDs and source metadata; it does not authenticate those identities. Quote presence does not decide whether the passage supports the conclusion. The reviewer examines the complete draft, including consequential assertions outside the registered claim lines. These responsibilities are part of the review procedure.

## Optional host integration

Hooks are omitted from the default manifest and enabled separately. The guard accounts for callbacks supplied by the host, rather than every network request, token or monetary charge. Ending a guard with `/drc end` ends that run; it does not certify a report.

The Stop audit checks a frozen snapshot and the rendered final text. Host interception determines which paths it can cover, and a Stop audit cannot retract text already generated. The renamed public package has isolated callback tests; live activation of this renamed version has not been measured.

Research evidence and work products remain under `<cwd>/research-workspaces/` after a guarded run. State lives under the host-provided `PLUGIN_DATA`. The package rejects its own directory and descendants as study roots. Its `.gitignore` applies to this repository, not to other study directories.

## Evaluation scope

The current package receipt records 59 offline tests on Python 3.15.2. Tests use synthetic records, simulated callbacks and temporary state. The synthetic example's review is a fixture, not an independent semantic assessment. Earlier live development cases have separate records and versions, described in [development-evaluation.md](development-evaluation.md).

The runtime requires Python 3.9 or later; Python 3.9 itself has not been tested in the recorded package run. The proposed CI workflow is inactive because the publishing authorisation lacks GitHub's workflow scope. There is no hosted CI result for this repository yet.

The published records do not provide a controlled estimate of comparative research accuracy, token savings or API cost. The workflow's targeted search, evidence reuse and lead accounting describe how effort is managed. They are distinct from a measured savings percentage.
